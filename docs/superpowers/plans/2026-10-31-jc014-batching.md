# 串口屏分批绘制修复计划

> **For agentic workers:** Use superpowers:executing-plans to implement this approved plan. Steps use checkbox syntax for tracking.

**Goal:** 完整显示 `321+123`，以及上半行 `321+123+`、下半行 `456+654`。

**Architecture:** 保留现有每行 8 字符、上半行 y=26、下半行 y=130 的排版。复用现有逐字符绘制路径，取消把整屏绘图指令拼成一串发送的模式；每个字符独立发送并等待处理时间。

**Tech Stack:** STM32F407、HAL UART4、FreeRTOS、Keil ARMCLANG；GCC 主机回归测试。

**Spec:** `DISPLAY_REQUIREMENTS.md`，及用户在本次聊天中对分批发送方案的明确同意。

## Global Constraints

- 上电全白；横屏；短数据显示在屏幕上半部分。
- `321+123` 完整显示在上半部分。
- `321+123+456+654` 的两行分别为 `321+123+`、`456+654`。
- 换行处的加号保留在上一行。
- 每个指令串不超过 500 字节，并以 CRLF 结束；绘图暂存区使用 480 字节。
- 每批等待完成后再发下一批；有 ACK 时也不能提前跳过该批所需绘图时间。

## Review Focus

- 无 ACK 的屏幕仍按绘图耗时等待。
- 提前 ACK 不造成下一批发送过早。
- 最多 16 字符、所有支持的数字与符号均不越界。
- 长数据换成短数据后清除下半部分旧内容。
- UART 发送失败后释放互斥锁，后续消息仍可显示。
