# 七段粗体与局部刷新 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this approved plan. Steps use checkbox syntax for tracking.

**Goal:** 保持数字实际字高 84 px（12.852 mm），减少完整绘制耗时；相同数据零刷新，位置不变时只更新变化字符。

**Architecture:** 仅在 `jc014.c` 中以七段矩形替换原字模，保留原坐标、间距、两行拆分与公共接口。在互斥锁内保存最近成功画面和类型；发送或清屏会使缓存失效，只有完整绘制成功才提交新缓存。相同排版按字符比较，行宽变化时只清除该行。

**Tech Stack:** STM32F407、HAL UART4、FreeRTOS、Keil ARMCLANG V6.16；GCC 主机测试。

**Spec:** `docs/superpowers/specs/2026-10-31-jc014-speed-design.md`，用户已明确批准。

## Global Constraints

- 字符单元仍为 35×84 px，间距 2 px，每行最多 8 字符，上下行 y=26/130。
- 所有数字的实际黑色笔画高度均为 84 px，包括 `1`；符号保持可读。
- `321+123+456+654` 上行 `321+123+`、下行 `456+654`。
- 每批不超过 500 字节，保留 ACK/无 ACK 两种等待路径。
- 重复数据不清屏、不发绘图命令；失败或外部画面操作后不得错误跳过重画。
- 本次在现有工程路径的 `feat/seven-segment-display` 分支工作，便于用户继续用 Keil 构建；不改动其他控制功能。

## Review Focus

- 重复数据在有无 ACK 时均不产生 UART 或额外等待。
- 单字符变化不得擦除未变化字符；行长度变化只重画受影响行。
- 清屏、裸绘图指令、部分绘制失败后，相同旧数据仍会正确重画。
- 所有数字、符号和 16 字符极限排版无裁剪或越界。
- 非大数字文本路径也应跳过完全相同的数据，切换回大数字时正确清除旧画面。
